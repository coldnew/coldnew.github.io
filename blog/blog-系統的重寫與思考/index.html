Blog 系統的重寫與思考

發表於 2026-11-07

隨著 AI Agent 越來越強大，開始思考是否一定要使用 org-mode 來進行 blog 或是筆記的撰寫，我自己的 blog system 因為歷史因素一直是使用 org-mode 撰寫原文，然後再用自己寫的系統發布成文章。

在這過程中，用過了好幾個不同的 static site generator, 比如 org-publish, emacs-blogit, pelican, hexo ... 等，每換一個我就撰寫對應的 plugin，將 org-mode 轉換成最終需要 render 的 HTML 網頁後讓他一起匯出成最終成果。

但用 org-mode 寫文章，如果是純文字的文章還好，最麻煩的應該就是需要導入圖片的狀況，會需要先將圖片拉到指定位置後，在 org-mode 內輸入圖片位置好方便生成器去找尋圖片並發布，這也佔用了不少撰寫文章的時間以及舒適度。

在用了 hexo 並撰寫 hexo-renderer-org 一段時間後，因為 nodejs 升級與 hexo 升級，後來我的 blog 就有相容性問題，但因爲當時很忙沒時間修正，因此導致我少寫了一些整理後的文章很長一段時間。

最近混用了 gpt-6.1-slow 和 opus 5.5 兩個不同的模型來幫我重新設計 blog 系統，一樣是產生 static site, 但是會建立一個 notion like 的伺服器，我直接在裡面使用 notion like 的編輯器編輯文章，最終編輯完成的文章，整體流程快很多，並且因為可以上傳圖片的關係，可以很方便的建立不同文章或筆記的雛形，之後再整理就可以發佈了，所以之後還是會慢慢地開始寫新的文章。

當然，也因為現在 AI 爬蟲眾多，開始有人說不要發佈自己寫的文章，不然都會被各家 model 吸收走，對於這一點我也還在思考，也許之後會引入廣告系統稍微賺點外快也說不定，但是否發佈文章是一件事，記錄筆記是另外一件事，只有自己吸收並整理得出來的才是自己的知識，這是我一貫的理念。
